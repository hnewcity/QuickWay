## 如何复测未通过的路径

在仓库根目录，使用已安装 OpenAI Python SDK 的环境。以下命令连接正在运行且已经授权的桌面版，不导出 Amazon 凭据；会使用真实模型额度。不要把代理密钥的内容写进命令或报告。

```sh
python scripts/smoke-openai.py --base http://127.0.0.1:8741 \
  --key-file "$HOME/Library/Application Support/dev.quickway.desktop/proxy.key" \
  --model quick-smart --effort low --parallel-tools
```

将 `--parallel-tools` 改成 `--protocol chat` 或 `--protocol responses` 可单独检查一条协议。测试必须看到结构化工具调用，以及工具结果中只有该客户端才知道的随机值；HTTP 200 或模型文字声称“已调用”都不算通过。不要为弥补漏调而自动重复有副作用的动作。

尚未确定漏调发生在云端工具注册、模型可见性还是自动选择环节。会话专属工具名消除了本地名称碰撞，但**不能据此断言已修复云端漏调**。这里没有测试 Windows 实机、其他账号权限、长期负载或全部固定型号。

## 补测：同一历史的并发断流（本地候选包）

两个客户端可能得到完全相同的聊天历史，因而使用同一个会话缓存键。用容量为 1 的本地通道让第一个流停在发送最后一个事件处，再让第二个请求完成并替换缓存，最后断开第一个流。旧逻辑会把第二个请求的缓存一起删掉。另一条非流式路径，即使接收方已经退出，也会保留无法继续的待回调会话。这两项在修改前都能稳定触发，不依赖模型是否配合、网络延迟或真实账号。

候选修复只允许流删除仍属于自己的缓存记录；非流式应答在确认有接收方后才提交缓存。另外覆盖了正常的流式应答：即使没有非流式接收方，客户端仍能收到结束事件并继续该会话。三个回归用例均通过。核心 / 网关 156、桌面 11、Python 21、界面 90，共 **278 项通过，7 项跳过**。两个 Rust 工程的 Clippy 和 release 版本检查通过。这是对断流问题的修复，**不是**对之前云端漏调原因的认定。

候选 Apple Silicon DMG 的 SHA-256 为 `db025af0343e7aca2798b549228b102021ea64aebea6137c96c3c7b3c92a759f`；已校验镜像、挂载副本的本地签名以及与构建输出的一致性。候选主程序 SHA-256 以 `f02d69cc` 开头。上表中的真实云端结果来自已安装且已授权的构建（主程序 SHA-256 以 `72564108` 开头），不挪作候选包的线上测试结果。

额外核对了在运行的桌面版：Messages、Chat Completions 和 Responses 三条路径对于强制工具选择都明确返回 HTTP 400，不会静默改为自动模式。这些校验不消耗模型额度。

随后用仅监听回环地址的模拟 WebSocket 对端补了两项回归。真实接收、解帧和 Chat Completions 转换代码在同一批消息里忽略了其他会话的回调，并把本会话的 `echo` 按原调用 ID 和参数恰好返回一次；仅收到“工具不可用”的普通文本时，则没有生成 `tool_calls`。两项均通过，核心 / 网关现为 158 项通过，各套件累计 **280 项通过、7 项跳过**。这两项测试未连接云端，不证明发生漏调的那次云端请求是否发过回调。改动仅限测试及报告，未替换运行中的程序，候选 DMG 校验值未变。
