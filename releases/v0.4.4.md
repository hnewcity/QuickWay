QuickWay 0.4.4 enables the cloud-tier route for enterprise App Integrations sign-ins and removes more internal Quick conversation markers from replies and restored history.

### Changes

- Personal (`social`) and enterprise (`enterprise`) App Integrations (AIDP) credentials can both reach the `quick-*` cloud tiers. Enterprise token renewal remains managed by Amazon Quick; account permissions are still enforced upstream.
- Gateway (`gateway` and `social_gateway`) profiles now receive an explicit unsupported-transport error instead of being treated as AIDP credentials.
- macOS cloud connections identify their platform as Mac.
- Repeated assistant/user conversation markers at the start of a line are removed, including `main` variants and marker-only lines. Fenced examples and inline prose are preserved. Restored assistant history is cleaned as well, so old leaked markers are not replayed.
- Includes the session isolation and disconnect fixes from 0.4.3.

### Verification and limits

- Local Windows checks: 159 core/HTTP gateway tests, 9 desktop tests, 21 release-tool tests and 44 Chromium UI tests passed (233 total). One live Codex test and three macOS-only UI checks were skipped. The frontend production build and Clippy with warnings denied for both Rust projects passed.
- Regression coverage includes enterprise request dispatch with synthetic credentials, supported-provider checks, marker filtering at every UTF-8 chunk boundary, history import, concurrent stream cleanup, WebSocket callbacks, and the local HTTP gateway.
- Enterprise cloud inference has not been verified with a real enterprise account. These changes do not claim to resolve the intermittent cloud tool-selection misses documented in the [0.4.3 macOS report](https://github.com/hnewcity/QuickWay/blob/v0.4.3/docs/QA-macOS-2026-11-22.md).
- GitHub Actions verifies Windows and macOS before publishing all three platform builds and signed in-app update packages.
